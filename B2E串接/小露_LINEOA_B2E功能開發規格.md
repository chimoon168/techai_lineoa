## 0. 共用規則

1. 圖文選單區塊用 Postback 觸發，經事件路由檢查綁定與 LINEOA 身份後，回覆開啟對應 LIFF。
2. 所有 B2E 呼叫走「小露 → B2E LINEOA 業務通道」（內網、mTLS＋HMAC），請求帶查詢人員員編；B2E 每次重查身份與線別，不信任小露端快取。
3. 寫入類（代理加減量、活動鎖檔、商談回覆）帶 `Idempotency-Key`，失敗不自動重試；完成後在聊天室留存結果卡片。
4. 商品編號用 LIFF 畫面上的數字鍵盤輸入（不叫出手機鍵盤），依類型限制長度：全聯貨號 8 碼、全聯條碼 8 或 13 碼、平台編號 8 碼、生鮮呼出碼 6 碼。一次一筆。
5. 只開放預購與箱購商品。以生鮮呼出碼查詢時，B2E 只回傳供應商 1431 善美的商品。
6. 採購只能查／操作自己負責線別的商品；廠服不限線別。
7. 不顯示商品成本、N特成本與折讓。

### 0.1 共用錯誤回應

| 情境 | HTTP / code |
| --- | --- |
| 查無商品 | 404 PRODUCT_NOT_FOUND |
| 非預購／箱購 | 422 PRODUCT_TYPE_NOT_ALLOWED |
| 生鮮呼出碼查到非善美商品 | 403 FRESH_CODE_SUPPLIER_NOT_ALLOWED |
| 採購查非本人線別 | 403 LINE_NOT_OWNED |
| 未綁定或身份無此功能 | 403 IDENTITY_NOT_ALLOWED |

## 1. 查詢商品（採購、廠服）

- API：`POST /api/lineoa/1.0/products/query`（`queryType`、`queryValue`、`employeeNo`）
- 顯示欄位：全聯貨號（供應商 1431 時附生鮮呼出碼）、全聯條碼、平台編號、全聯分類、供應商（4 碼＋名稱）、商品名稱、銷售稅別（0 應稅／2 免稅）、品牌、銷售名稱、銷售規格、最新市價、最新售價、商品採購、商品主管、銷售狀態（1 可銷售／2 銷售不可／5 已下市／9 已除帳）、變價活動、最新可銷量、商品主圖。
- 同一編號對應多筆平台商品時，顯示可銷售的一筆，並提示改用平台編號查詢。

## 2. 查詢特賣（採購、廠服）

對應 B2E「全聯預購變價查詢」。

- API：`POST /api/lineoa/1.0/price-changes/query`
- 查詢方式：
  - 依商品：四種編號擇一。
  - 依檔期：選檔期，採購只列自己線別。
- **變價狀態只回傳四種**：

  | 代碼 | 狀態 |
  | --- | --- |
  | 1 | 待生效 |
  | 2 | 已變價 |
  | 4 | 已作廢 |
  | 10 | 已中止 |

- **只回傳近期 10 筆**：依活動起日由新到舊排序，取前 10 筆；回應帶 `total`，超過 10 筆時畫面提示「共 N 筆，顯示近期 10 筆」。
- 請求參數：`queryType`／`queryValue` 或 `eventCode`、`statuses:[1,2,4,10]`、`limit:10`、`sort:"activityStart desc"`、`employeeNo`。
- 列表欄位：變價狀態、檔期、活動起迄、原價／市價、活動售價、提貨方式、銷售門市、限制數量。
- 明細欄位：另含 N特（組數／售價）、取貨門市（店群）、提貨起迄（宅配由系統計算）、出貨（廠出／物流）、目前可銷量、活動銷售碼、紙本訂購碼。
- 採購可從明細對 1 待生效、2 已變價且活動未過期的變價直接鎖檔（轉第 4 節）。
- 修改變價欄位不在 LINE 處理，請至 B2E「全聯預購變價異動」。

## 3. 代理加減量（限 20 全聯採購）

對應 B2E「預購可銷量異動審核」。採購代理供應商送審，並自動核可（autopass）。

- API：`POST /api/lineoa/1.0/purchase-adjustments`
- 請求：`pxNo`、`platformNo`、`adjustType`（INCREASE／DECREASE）、`qty`、`reason`、`employeeNo`、`proxyForSupplier`、`autoApprove:true`
- 畫面：目前可銷量、7 日內銷量、30 日內銷量 → 加量／減量 → 數量（數字鍵盤）→ 申請原因 → 即時顯示核可後可銷量（預估），≤0 標示「將歸零」。
- 申請原因：檔期加開、補貨到貨、熱銷追加、原料不足、廠商產能調整、停產減量、其他。
- 注意事項：
  1. 依核可當下的庫存加減量；減量大於目前庫存時，庫存減為 0。
  2. 庫存為線上、線下共用。
  3. 此作業用於當下追加或調整可銷量，**不影響提品變價的限制數量**。
- 回應：申請單號、審核狀態 APPROVED（AUTOPASS）、調整前後可銷量；通知供應商。
- 待確認：申請人與核可人皆記錄為該採購，是否符合 B2E 稽核要求。

## 4. 活動鎖檔（限 20 全聯採購）

對應 B2E「全聯檔期變價狀態(鎖檔)」。

- API：`POST /api/lineoa/1.0/price-changes/lock`（`priceChangeIds`、`reason`、`employeeNo`）
- 依檔期（只列活動進行中、活動未開始的檔期）或商品編號查詢。
- **只列變價狀態 1 待生效、2 已變價**（且活動未過期）的變價，可多選。
- 鎖檔原因必填：商品品質問題、供應商無法供貨、價格設定錯誤、檔期取消；可另補充 100 字內說明。送出前二次確認。
- 鎖檔後變價狀態改為 **10 已中止**；全電商立即失效，線下門市隔天失效（待 POS 同步）；無法復原，需重新提報變價。

## 5. 全聯檔期（採購、廠服，唯讀）

對應 B2E「全聯行銷檔期」。

- API：`GET /api/lineoa/1.0/marketing-events`
- 日期：**活動起迄**、**報名起迄**。不顯示開放／未開放報名。
- 狀態分兩列，可各自篩選：

  | 列 | 狀態 | 判斷 |
  | --- | --- | --- |
  | 報名 | 報名未開始／報名進行中／報名已結束 | 今天與報名起迄比較 |
  | 活動 | 活動未開始／活動進行中／活動已過期 | 今天與活動起迄比較 |

- 明細：檔期代碼、名稱、活動起迄、報名起迄、報名狀態、活動狀態、各變價狀態筆數（採購為自己線別）；可跳到該檔期的特賣清單。
- 調整報名起迄仍在 B2E 操作。

## 6. 商談回覆（限 20 全聯採購）

對應 B2E「全聯商談查詢」與 SCM「廠服商談作業」。

- API：`GET /api/lineoa/1.0/inquiries`、`POST /api/lineoa/1.0/inquiries/{no}/replies`
- **商談類型三擇一，且只對應一筆**：

  | 商談類型 | 值 | `originType` |
  | --- | --- | --- |
  | 子單 | 單一子單號（TS／AS／ES） | ORDER |
  | 商品 | 單一商品（全聯貨號／條碼／平台編號…） | PRODUCT |
  | 功能 | 單一功能（貨號申請／加減量／變價…） | FUNCTION |

  不會有一筆商談涵蓋多張子單或多個商品。SCM 若勾選多張訂單發起，應拆成每張子單各一筆商談（待與 SCM 確認）。
- 新商談由小露推播通知；列表可篩待回覆／已回覆／已結案，未讀以紅點標示。
- 子單與商品類可直接查看該商品的特賣；功能類不連結商品。
- 回覆 500 字內，可用快速片語；可「回覆並結案」，結案後不能再回覆。只列指派給該採購的商談；回覆後通知供應商。
- 待確認：商談主題（第二層分類）清單。

## 7. 不在本版範圍

- 廠服「發起商談」。
