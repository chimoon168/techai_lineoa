## 二、與企劃不同的地方（請確認）

### 1. 刪除／停用身份時，會自動把人員改為「基本使用者」

企劃原型的刪除提示只寫「可能影響已設定使用此身份的通知規則」。**依 SA 後續提供的規則**改為：

> 跳出警告告知「目前有 N 個帳號綁定此身份」，確認後**自動將這些帳號改為「10 基本使用者」**，接著才停用或刪除該身份。

停用也適用同一流程。另外**「10 基本使用者」設為系統保留身份，不可停用也不可刪除**（因為它是其他身份被移除時的去處）。

### 2. 編輯身份時，Id 改為不可修改

企劃原型允許編輯時修改 Id，實作改為**唯讀**。原因是這個 Id 是 LINE OA 端用來辨識身份的依據（對應 Rich Menu 等行為），改號會讓已設定的人員與下游對不上。

> 若要換號，正確做法是「停用舊的、新增一筆」。**如果 SA 仍希望可以改號，請告知**，需要另外處理連動更新。

### 3. 人員角色頁的查詢條件新增「LINEOA身份」下拉

企劃原型沒有這個篩選，依後續需求追加。可篩「全部／未設定／指定身份」，其中選「未設定」能一次找出所有**沒有 LINE OA 使用資格**的帳號。

### 4. 身份 Id 自動編號為 +10

留空時系統自動給號，沿用企劃的 10/20/30 慣例以 **+10** 遞增（例如現有最大為 50，下一筆給 60），中間留插號空間。

## 三、一個重要的資料語意，請 SA／PM 一併與 LINE OA 端確認

人員的 LINEOA 身份有**三種狀態**，其中兩種容易被混淆：

| 狀態 | 意義 |
| --- | --- |
| **未設定**（畫面顯示灰色「未設定」） | 該帳號**沒有使用 LINE OA 的資格** |
| **10 基本使用者**（畫面顯示藍色） | **有資格**，但只提供基本服務 |
| 其他身份（畫面顯示綠色） | 一般身份 |

「未設定」與「基本使用者」是**兩種不同狀態**，系統不會自動互換。人員角色頁把身份「取消」代表**收回該帳號的 LINE OA 資格**，而不是降級為基本使用者。

畫面已用三種顏色區隔，避免維護人員誤判。**請確認 LINE OA 端的行為設計與此一致。**

1. **交付串接文件給 LINE OA 端開發者**，已備妥兩份（身份 API 規格、事件規格）。

3. **請確認 LINE OA 端是否需要「某身份底下有哪些人」的反查功能** — 目前只提供「依人員查身份」的正向查詢。企劃說明身份是「供公告、審核等通知功能選擇發送對象使用」，但未載明展開名單由哪一側負責；若 LINE OA 端需要由 B2E 提供，需另開需求。
