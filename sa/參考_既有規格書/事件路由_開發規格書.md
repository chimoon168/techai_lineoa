## 1. 名詞（LINE 官方用語）

| 用語 | 說明 |
| --- | --- |
| Rich menu area action | 圖文選單每個區塊的動作。UAT 已支援 Message、URL / LIFF、Postback 三種 |
| Message action → Message event | 點區塊等於使用者打出一段文字；使用者自己打字也會產生同樣的 Message event |
| Postback action → Postback event | 點區塊送出隱藏的 `data`（如 `action=product_query`），可設定 Display Text |
| URI action | 直接開網址或 LIFF，不經過 Webhook |
| Webhook | LINE 把上述事件送到小露後端，由小露決定要做什麼 |

本畫面管理的就是「Webhook 收到 Message／Postback event 之後的路由」，簡稱**事件路由**。

## 2. 現況（UAT 2026-10-07 盤點）

- 左側選單：每日語音、日結摘要、LINE OA 圖文選單管理。
- 圖文選單列表：目前 0 筆。
- 新增圖文選單：
  - 基本設定：名稱、選單類型（未綁定使用者／已綁定一般使用者／LINE OA 身分類選單／自訂）、版型（半版 2 格／全版 4 格／全版 6 格）、選單列文字（≤14 字）、進入聊天室時預設展開。
  - 圖片：PNG／JPEG ≤1 MB，尺寸依版型（半版 2500×843）。
  - 區塊動作：每格選 Message（Label＋訊息文字）、URL / LIFF（Label＋URL）、Postback（Label＋Postback Data＋Display Text）。
  - 儲存草稿／儲存並發布。
- **缺口**：圖文選單只負責「送出什麼」，沒有地方設定「小露收到後做什麼」。Postback Data 是自由輸入，容易和後端不一致。

## 3. 設計原則

1. 一筆路由＝一個功能入口。Postback data 與關鍵字可同時指到同一筆路由，權限與動作只設定一次。
2. 比對順序：Postback data 完全相符優先；其次依「優先序」由小到大比對關鍵字。
3. 權限以 B2E 的 LINEOA 身份為準；`未設定身份`（null）一律擋下，不等於 10 基本使用者。
4. Webhook 只能回覆訊息，不能直接開 LIFF。選「開啟 LIFF」時回覆附按鈕的卡片；要點選單直接開 LIFF，區塊動作改用 URL / LIFF。
5. 業務資料（查詢商品等）預設只在 1 對 1 聊天使用。

`cfg_event_route_identities`：route_id、identity_id

`cfg_event_route_params`：route_id、param_name、source_type、fixed_value、sort

`log_event_dispatch`：event_id、line_user_id、event_type、raw_text／postback_data、route_id、result（MATCHED／NO_MATCH／DENY_UNBOUND／DENY_IDENTITY／API_FAIL）、latency_ms、create_on
