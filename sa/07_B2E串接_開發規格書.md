## 2. LINE OA 身份語意（B2E 規格重點）

| 值 | 語意 |
| --- | --- |
| null／欄位不存在 | 無 LINE OA 資格 → 拒綁／解綁 |
| 10 基本使用者 | 有資格、基本服務；系統保留，不可停用／刪除 |
| 20／30／40／50 | 全聯採購／全電商MD／全聯行銷／廠服 |
| 90 | 小露SYSOP（後台權限） |

- 一人至多一個身份。
- 身份 Id 可能被刪除後重用、名稱可能被改 → 不長期快取對應。
- 刪除／停用身份時，B2E 自動把人員改為 10。

## 3. Kafka 快照處理

| 項目 | 規格 |
| --- | --- |
| Topic | `PXB2E.Internal.MemberSnapshotChanged` |
| Key | `MemberId`（同一人依序抵達，但 B2E 不保證不會舊蓋新） |
| 格式 | JSON、PascalCase；完整快照，非差異 |
| 重要欄位 | `MemberId`、`Account`、`Status`、`LineOaIdentity { IdentityId, IdentityName }` |

處理步驟：

1. （可選）以 `Uuid` 去重，僅為省成本。
2. 只處理有有效綁定的員工；無綁定者忽略。
3. 直接覆蓋，不以 `MemberUpdateOn`／`Uuid` 判斷新舊。
4. 依 Status 與 LineOaIdentity 套用 02 的狀態矩陣（`null` 是明確值，必須清除身份）。
5. 偶發舊蓋新由 Reconcile Job 收斂。

## 4. 身份查詢 API

| 項目 | 規格 |
| --- | --- |
| 認證 | `Authorization: Bearer {32 字元系統 token}`（非使用者 token） |
| 參數 | `account` 或 `employeeNumber` 擇一 |
| 回應 | `found=false` 查無此人；`found=true, identity=null` 無資格；`found=true, identity=物件` 正常 |

## 5. 業務 API（下一階段）

依網路架構 v0.2：**不另開小露專屬 Gateway，直接沿用 B2E 既有 API 服務。**

- 業務 API 由 B2E 掛在既有 API 服務上，與身份查詢 API 同一入口；路徑暫列 `/api/lineoa/1.0/*`（正式前綴待 B2E 確認）。
- 認證沿用 B2E 系統對系統 Bearer token＋來源 IP 白名單＋限流；不採 v0.1 的 mTLS／HMAC 專屬通道。
- 不與 OIDC 混用；業務授權不放在 OIDC scope。
- 代理呼叫：帶 `X-Acting-Member`（綁定的 MemberId）、`X-Line-User-Id`；寫入類帶 `Idempotency-Key`。
- B2E 每次請求重驗在職、身份與功能權限，不信任小露快取。
- 共用入口的補強：B2E 需能針對小露 client 限流／停權；token 定期輪替；呼叫寫稽核。

## 6. 網路通道

| # | 通道 | 方向 | 防護 |
| --- | --- | --- | --- |
| 1 | LINE Webhook | LINE → WAF → 小露 | X-Line-Signature |
| 2 | 小露出站 | 小露 → LINE API、Gemini、AWS SES／S3 | Proxy FQDN 白名單 |
| 3 | B2E OIDC 前端 | SYSOP 瀏覽器 → B2E authorize | redirect_uri 白名單、PKCE |
| 4 | B2E OIDC 後端 | 小露 → token／userinfo | client secret |
| 5 | B2E 既有 API（直連） | 小露 → B2E 既有 API 服務（員工查核、身份查詢、業務 API） | 系統 Bearer token、來源 IP 白名單、限流；建議內網 |
| 6 | Kafka | 小露 ← B2E broker | SASL/TLS，帳號由 B2E 發放 |

詳見 09 小露 × B2E 網路架構 v0.2。
