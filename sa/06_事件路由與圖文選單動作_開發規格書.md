## 1. 圖文選單三種動作

| 動作 | 範例 | 處理方式 | 11/16 現況 |
| --- | --- | --- | --- |
| MESSAGE｜文字指令 | 「綁定帳號」「查詢摘要」 | LINE 送出訊息 → Webhook 辨識 → 回覆／執行預設邏輯 | 已支援 |
| URI｜開啟網址 | LIFF 語音列表、身份相關服務 | 開啟 URL → **目的地重新驗證 LINE 身份／權限** | 已支援 |
| POSTBACK｜事件參數 | `action=product_query` | 送出隱藏 data 到 Webhook | 選單設定已支援；**Webhook 尚未做業務分流** |

注意：

- MESSAGE 送出的任意文字，不代表會自動生成對應功能；Webhook 須有對應邏輯。
- URI 不是授權；URI 目的頁必須自行驗證。
- Webhook 只能回覆訊息，不能直接開 LIFF；要直接開 LIFF 用 URI 動作。

## 2. 下一階段：事件路由

目標：Webhook 收到 Message／Postback 後，依後台「事件路由」決定權限與動作，讓各身份專屬選單可上線。

**處理流程**：LINE → Webhook → 事件路由比對 → 權限檢查（02 的狀態矩陣＋路由允許身份）→ 執行動作。

| 規則 | 說明 |
| --- | --- |
| E1 | 一筆路由＝一個功能入口；Postback data 與關鍵字可指向同一路由 |
| E2 | Postback data 完全相符優先；其次依優先序比對關鍵字 |
| E3 | 身份 null 一律擋下，不等於 10 |
| E4 | 動作：開啟 LIFF（回覆附按鈕卡片）／呼叫 API／只回覆訊息 |
| E5 | 業務資料預設只在 1 對 1 聊天使用 |
| E6 | Status 2 的凍結攔截在統一入口完成，先於路由 |

**初始路由（沿用 v0.1，狀態為規劃值）**

| 代碼 | Postback data | 關鍵字 | 綁定 | 身份 | 動作 |
| --- | --- | --- | --- | --- | --- |
| BIND | action=bind | 綁定、帳號綁定 | 須未綁定 | — | LIFF 帳號綁定 |
| UNBIND | action=unbind | 解除綁定 | 須已綁定 | — | 解除綁定 |
| HELP | action=help | 說明、help | 不限 | — | 回覆說明 |
| PRODUCT_QUERY | action=product_query | 查詢商品、查商品 | 須已綁定 | 20、50 | LIFF 查詢商品（見 08） |
| SALE_QUERY | action=sale_query | 查詢特賣 | 須已綁定 | 20、50 | LIFF → B2E price-changes/query |
| EVENT_CALENDAR | action=event_calendar | 全聯檔期、檔期 | 須已綁定 | 20、50 | LIFF → B2E marketing-events |
| INQUIRY_REPLY | action=inquiry_reply | 商談回覆 | 須已綁定 | 20 | LIFF → B2E inquiries |
| PURCHASE_ADJUST | action=purchase_adjust | — | 須已綁定 | 20 | LIFF → B2E purchase-adjustments |
| PRICE_LOCK | action=price_lock | — | 須已綁定 | 20 | LIFF → B2E price-changes/{id}/lock |

表中 B2E API 皆走 B2E 既有 API 服務直連，不另開 Gateway（見 07 §5、09）；事件路由後台的「呼叫 API 通道」選項，v0.1 的「B2E LINEOA 業務通道」改為「B2E 既有 API」。

資料表草案（`cfg_event_routes` 等）、後台畫面欄位見參考：事件路由規格 v0.1 §4–7。

## 3. 驗收條件（下一階段）

- 選單 Postback 格點擊後，依路由執行；未設定路由的 data 回覆預設訊息。
- 權限不符、未綁定、凍結各回覆對應訊息。
- 對應測試：測試規格 v2.0 RM-09、RM-13。
